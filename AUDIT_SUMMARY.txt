ISSUE #2: FRONTEND QUERIES LACK STORE_ID FILTER (🔴 CRITICAL)

Location: All frontend pages (Dashboard, Products, Reorder, Alerts, Suppliers)
Severity: CRITICAL - DATA BREACH
Problem: No `.eq('store_id', storeProfile.id)` filter on queries

Code Example (Dashboard.jsx line 35):

                Alerts.jsx, Deliveries.jsx, QuickUpdate.jsx
Fix: Add store_id filter to EVERY Supabase query
Effort: 4 hours
Priority: DO SECOND (after RLS)

ISSUE #3: DESTRUCTIVE DELETE-AND-RECREATE (🔴 CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Location: WF-03 (line 84) and WF-05 (line 225)
Severity: CRITICAL - DATA LOSS
Problem: Deletes ALL records (not just outdated ones)

Delete Query:
  DELETE FROM "Stock Alerts" WHERE id=not.is.null
  
This deletes EVERY alert, including:
  - Dismissed alerts
  - Alert history/audit trail
  - last_alerted_at timestamps

Failure Scenario:
  1. WF-08 runs at 8 AM → creates alerts, sends WhatsApp
  2. User dismisses alert at 8:15 AM
  3. WF-08 runs again (manual trigger or scheduled)
  4. ALL alerts deleted (including dismissed one)
  5. Dismissed alert reappears as Active
  6. User confused by duplicate alert

Impact: 
  - Lost alert history
  - Broken anti-spam filter (last_alerted_at erased)
  - Repeated WhatsApp notifications
  - User dismissals ignored

Fix (CONDITIONAL DELETE):
  DELETE FROM "Stock Alerts"
  WHERE store_id = 'X' 
    AND product_id NOT IN (
      SELECT product_id FROM Products 
      WHERE store_id = 'X' AND current_stock <= reorder_threshold
    )

Effort: 3 hours (fix in 2 workflows)
Priority: DO THIRD

ISSUE #4: WEBHOOK AUTHENTICATION MISSING (🔴 CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Location: WF-01, WF-06, WF-07 (all n8n workflows)
Severity: CRITICAL - EXTERNAL ATTACK SURFACE
Problem: No API key validation on any webhook

Attack Example:
  # Attacker adds malicious product to any store
  curl -X POST "https://n8n.example.com/webhook/product-sales-ingest" \
    -H "Content-Type: application/json" \
    -d '{
      "product_id": "MALWARE_001",
      "product_name": "Hacked",
      "current_stock": 999999,
      "avg_daily_sales": 0,
      "reorder_threshold": 1
    }'
  
  → Malicious product added to database

Impact: 
  - System can be spammed with fake products
  - Data pollution
  - DDoS risk
  - No audit trail

Fix (in each webhook):
  const apiKey = $json.headers['X-API-Key']
  if (!apiKey || apiKey !== process.env.N8N_API_KEY) {
    throw new Error('Unauthorized: Invalid API key')
  }

Effort: 1 hour (5-15 min per webhook)
Priority: DO EARLY

ISSUE #5: NO INPUT VALIDATION IN WF-01 (🔴 CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Location: WF-01 Product Ingestion
Severity: CRITICAL - DATA CORRUPTION & INJECTION ATTACKS
Problem: Accepts any values without validation

Attack Examples:
  // Negative values
  {"product_id": "TEST", "current_stock": -99999, "avg_daily_sales": -50}
  
  // SQL injection
  {"product_id": "'; DROP TABLE Products; --"}
  
  // Extreme values
  {"product_id": "X", "unit_price": 99999999999}
  
  // Missing fields
  {"product_id": "incomplete"}

Impact: 
  - Data corruption
  - System crashes
  - Potential SQL injection
  - Invalid calculations downstream

Fix: Validate before database operations
  - product_id: non-empty string, max 50 chars
  - current_stock: non-negative integer, < 1,000,000
  - avg_daily_sales: non-negative number
  - reorder_threshold: non-negative integer
  - unit_price: positive number
  - Check for required fields

Effort: 2 hours
Priority: DO EARLY
